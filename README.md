# Outreach Sender

تطبيق بسيط لإرسال إيميلات Outreach لأكتر من شركة، و **Google Sheets هو قاعدة البيانات**:
كل شركة = شيت واحد فيه بيانات الشركة، إعدادات الإيميل المرسل، القوالب، إعدادات monday، جهات الاتصال، حالة الإرسال، الجدولة والسجل.
التطبيق بيعمل كل حاجة: تجهيز الشيت، الإعدادات، الاستيراد، الإرسال اليدوي والمجدول والتلقائي، واكتشاف الردود والارتدادات، ومزامنة monday.

> التقنيات: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui على Vercel · Google Sheets API (Service Account) · SMTP (nodemailer) · IMAP (imapflow) · monday GraphQL.

---

## تجربة سريعة (الوضع التجريبي)

بدون أي حسابات حقيقية — شيت وهمي في الذاكرة + SMTP/IMAP/monday وهميين:

```bash
npm install
```

```bash
DEMO=1 npm run dev
```

افتح `http://localhost:3000` — كلمة المرور: `demo`.
الوضع التجريبي يعمل تلقائيًا أيضًا لو `GOOGLE_SERVICE_ACCOUNT_JSON` غير مضبوط (مفيد لـ Preview deployments على Vercel).

في الوضع التجريبي: أي إيميل فيه `fail` يفشل إرساله، وفيه `bounce` يرتد، وكلمة سر SMTP فيها `wrong` تعطي خطأ تسجيل دخول، ورابط شيت فيه `noaccess` يعرض خطوة المشاركة.

## الإعداد خطوة بخطوة (≈ 10 دقائق)

### 1) إنشاء Service Account وتفعيل Sheets API
1. افتح [Google Cloud Console](https://console.cloud.google.com/) وأنشئ مشروع جديد (أو استخدم مشروع موجود).
2. من **APIs & Services ← Library** ابحث عن **Google Sheets API** واضغط **Enable**.
3. من **IAM & Admin ← Service Accounts** اضغط **Create service account** (أي اسم، مثلاً `outreach-sender`) — لا تحتاج أي Role.
4. افتح الـ Service Account ← تبويب **Keys** ← **Add key ← Create new key ← JSON**. سيتم تحميل ملف JSON.
5. احتفظ بالإيميل الموجود في `client_email` (شكله `...@....iam.gserviceaccount.com`) — ستشارك معه الشيتات.

### 2) إنشاء شيت الـ Registry
1. أنشئ Google Sheet جديد فارغ (مثلاً اسمه `Outreach Registry`).
2. شاركه مع إيميل الـ Service Account بصلاحية **Editor**.
3. انسخ الـ ID من الرابط: `https://docs.google.com/spreadsheets/d/`**`هذا-هو-الـ-ID`**`/edit`
4. التطبيق ينشئ تلقائيًا تبويب `Companies` (Name | Sheet URL | Color | Active) وتبويب `System` (لصحة المجدول).

### 3) النشر على Vercel وضبط المتغيرات
1. اربط الـ repo بـ Vercel (Git integration).
2. في **Project ← Settings ← Environment Variables** أضف (لـ Production):

| المتغير | القيمة |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | محتوى ملف JSON كاملًا (سطر واحد) |
| `REGISTRY_SHEET_ID` | ID شيت الـ Registry |
| `APP_PASSWORD` | كلمة مرور الدخول للتطبيق |
| `APP_SECRET` | نص عشوائي طويل (32+ حرف) — **لا تغيّره بعد البدء** لأنه يشفّر كلمات السر في الشيتات |
| `CRON_SECRET` | نص عشوائي لحماية رابط المجدول |
| `APP_URL` (اختياري) | رابط التطبيق العام لروابط إلغاء الاشتراك (الافتراضي: رابط Vercel الأساسي) |

لتوليد قيمة عشوائية:

```bash
openssl rand -base64 36
```

3. أعد النشر (Redeploy). لو تركت متغيرات Preview فارغة، الـ Preview يعمل بالوضع التجريبي.

### 4) تشغيل المجدول (cron)
المجدول هو `GET /api/cron?key=CRON_SECRET` (أو header `Authorization: Bearer CRON_SECRET`) ويجب استدعاؤه كل 5–10 دقائق. في كل استدعاء ولكل شركة نشطة: ينفذ التشغيلات المجدولة المستحقة ← دفعة الإرسال التلقائي ← فحص الوارد (IMAP) للردود والارتدادات. كل استدعاء ينتهي خلال ~50 ثانية ويكمل الباقي في المرة القادمة.

**الخيار أ — GitHub Actions (موصى به، كل 10 دقائق):**
الملف جاهز: `.github/workflows/cron.yml`. فقط أضف في GitHub: **Settings ← Secrets and variables ← Actions ← New repository secret**:
- `CRON_URL` = `https://<your-app>.vercel.app/api/cron`
- `CRON_SECRET` = نفس قيمة `CRON_SECRET` في Vercel

ثم من تبويب **Actions** فعّل الـ workflow (ويمكن تشغيله يدويًا بـ **Run workflow** للتجربة).
> ملاحظة: GitHub قد يؤخر الـ schedule بضع دقائق أحيانًا، وهذا طبيعي.

**الخيار ب — Vercel Cron:**
`vercel.json` فيه cron يومي (خطة Hobby تسمح بمرة يوميًا فقط). على خطة Pro يمكن تغييره إلى `*/10 * * * *`. Vercel يرسل `Authorization: Bearer CRON_SECRET` تلقائيًا.

**صحة المجدول:** صفحة الشركات ولوحة التحكم تعرض «صحة المجدول» (آخر استدعاء)، وتحذر لو لم يحدث استدعاء خلال 30 دقيقة.

### 5) إضافة شركة
1. أنشئ Google Sheet جديد فارغ للشركة.
2. في التطبيق: **الشركات ← إضافة شركة** ← اكتب الاسم والصق رابط الشيت ← **فحص الوصول**.
3. لو ظهر إيميل الـ Service Account: انسخه (زر نسخ) وشارك الشيت معه كـ **Editor** ثم اضغط «فحص الوصول» مرة أخرى.
4. اضغط **تجهيز الشيت** — ينشئ كل التبويبات والأعمدة (بدون المساس بأي بيانات موجودة). زر **إصلاح الشيت** في الإعدادات ← متقدم يعيد نفس العملية لاحقًا.

تبويبات الشيت: `Company`, `Sender`, `Monday`, `Templates`, `Contacts`, `Send Log`, `Schedule`, `Do Not Contact`, `Activity`, `Mappings`.
يمكنك إعادة ترتيب الأعمدة أو إضافة أعمدة — التطبيق يقرأ الأعمدة بالاسم وليس بالمكان. أي عمود في Contacts متاح في القوالب كـ `{column_name}`.

### 6) Gmail / Google Workspace — App Password
1. فعّل **التحقق بخطوتين** في حساب Google.
2. افتح [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) وأنشئ App Password باسم `Outreach`.
3. في التطبيق: **الإعدادات ← الإيميل المرسل** ← اضغط «Gmail / Workspace» لملء الإعدادات:
   - SMTP: `smtp.gmail.com` منفذ `465` Secure = نعم
   - IMAP: `imap.gmail.com` منفذ `993`
   - SMTP User = إيميلك، SMTP Password = الـ App Password (16 حرف بدون مسافات)
4. اضغط **اختبار SMTP** ثم **اختبار IMAP** ثم **إرسال إيميل تجربة**.
5. شغّل **فحص قابلية التسليم** (SPF / DKIM / DMARC / MX) ونفّذ الإصلاحات المقترحة.

> كلمات السر وتوكن monday تُحفظ في الشيت **مشفرة** (`enc:...` بـ AES-256-GCM) ولا تُرسل للمتصفح أبدًا. لو كتبت كلمة سر عادية مباشرة في الشيت، التطبيق يقبلها ويعيد حفظها مشفرة.
> Outlook / 365: `smtp.office365.com:587` (Secure = لا) و `outlook.office365.com:993`. Zoho: `smtp.zoho.com:465` و `imap.zoho.com:993`.

### 7) توكن monday
1. في monday: الصورة الشخصية ← **Developers** ← **My access tokens** ← انسخ التوكن.
2. في التطبيق: **الإعدادات ← monday** ← الصق التوكن ورابط البورد (أو رقمه) ← **تحميل البورد**.
3. اختر الجروب، ومتى يُنشأ العنصر (عند أول إرسال / عند الاستيراد / أبدًا)، واربط كل حقل بعمود من القوائم. زر **إنشاء الأعمدة الناقصة** ينشئها لك.
4. **اختبار** ينشئ عنصر تجربة ويحذفه.
لو فشل monday، الإيميل يبقى محسوبًا كمُرسل، والحالة تظهر `Failed: السبب` مع زر إعادة المحاولة.

### 8) أول إرسال تجربة
1. **القوالب**: فعّل قالب أول رسالة (Step 0) لكل لغة تستخدمها، وراجع المعاينة الحية مع جهة اتصال حقيقية، واضغط **إرسال تجربة لي**.
2. **جهات الاتصال ← استيراد**: أضف جهة اتصال واحدة بإيميلك الشخصي (حالة «جاهز»).
3. **الإرسال ← إرسال يدوي**: «اختيار جهات» ← اكتب الـ ID ← **معاينة** ← **إرسال** ← تأكيد. تابع التقدم مباشرة.
4. رد على الإيميل من بريدك، ثم من لوحة التحكم اضغط **فحص الوارد الآن** — ستتحول الحالة إلى «ردّ» وتتوقف المتابعات.
5. لما يكون كل شيء سليم: شغّل **الإرسال التلقائي** من لوحة التحكم.

## تنسيق القوالب
- محرر النص في صفحة القوالب يدعم: عريض/مائل/تحته خط، الخط والحجم، لون النص ولون الخلفية، المحاذاة، القوائم.
- **رابط داخل كلمة:** ظلّل الكلمة (مثلًا «رابط التسجيل») واضغط زر الرابط والصق الرابط — أو اكتب متغيرًا مثل `{booking_link}` كرابط.
- النص يُحفظ في عمود `Body` بالشيت كـ HTML. القوالب القديمة (نص عادي) تعمل كما هي وتتحول لـ HTML عند أول تعديل.
- كل إيميل يُرسل بجزأين: HTML المنسق + نسخة نص عادي (الروابط تظهر كـ «النص (الرابط)»).
- استخدم الخطوط الآمنة للإيميل الموجودة في القائمة فقط، لأن برامج البريد لا تحمّل خطوطًا خارجية.

## منطق الإرسال (مختصر)
- الترتيب: المتابعات المستحقة أولًا (Sent / Follow-up N و Next Send At ≤ الآن)، ثم الجهات «جاهز» (والإرسال اليدوي/المجدول يشمل «جديد» أيضًا).
- يتم تخطي: الإيميل غير الصالح، قائمة عدم التواصل (إيميل أو دومين)، المكرر، ومن ردّ/ارتد/ألغى الاشتراك.
- الحد اليومي يُحسب من صفوف `Sent` في Send Log بتوقيت الشركة، ولا يمكن تجاوزه أبدًا. الإرسال اليدوي فقط يمكنه تجاوز نافذة الإرسال بعد تأكيد.
- القالب حسب الخطوة واللغة؛ نسخة A/B تُختار بثبات حسب ID الجهة وتستمر في المتابعات.
- أي متغير فارغ = لا يُرسل (ويتوقف الإرسال التلقائي مع تنبيه).
- المتابعات في نفس المحادثة: `In-Reply-To` و `References` وعنوان `Re: <عنوان أول رسالة>`.
- كل إيميل: From Name، Reply-To، `List-Unsubscribe` (+ One-Click)، نص عادي + HTML (RTL للعربي).
- **التوزيع (Pacing):** الحد اليومي يتوزع بالتساوي على نافذة الإرسال (مثلاً 30 في نافذة 9–13 ← إيميل كل ~8 دقائق).
- **الأمان:** الإرسال التلقائي لا يبدأ قبل نجاح اختبار SMTP ووجود قالب Step 0 مفعّل لكل لغة مستخدمة، ويتوقف تلقائيًا عند: نسبة ارتداد عالية (بعد 20 إرسال)، فشل تسجيل دخول SMTP 3 مرات متتالية، أو متغير فارغ.
- قفل لكل شركة (خلية `Lock` في تبويب Sender) يمنع تشغيلين في نفس الوقت.
